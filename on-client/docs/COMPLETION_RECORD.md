## 4. 같은 최종 소스와 패키지, 다시 실행한 기록
프로젝트 폴더에서 git rev-parse HEAD로 최종 커밋 번호를 확인하고, GitHub 저장소 화면에도 같은 커밋이 올라가 있는지 봅니다. 값을 찾지 못하면 미확인으로 둡니다. 포장을 해 봤다면 그때 만든 묶음의 경로만 적고, 다른 폴더의 파일과 섞지 않습니다.
- 실행 환경(OS, Node 버전): Windows + Node 24.19.0 권장 / [클라우드 확인] Linux + Node 22.23.4
- 필요한 연결·파일·사전 설치물: Node.js 만 필요(외부 npm 패키지·관리자 권한·API 키 불필요). 실제 SDP 연결에는 접근 제어 서버·연결 어댑터·개인 인증서 필요(이번 과정에서 발급 없음)
- 최종 소스 커밋: 미확인 (E:\chesed 에서 commit·push 뒤 `git rev-parse HEAD` 값을 적음)
- 실행 패키지 경로: 해당 없음 — 포장(`npm run package-app`)은 이번 과정에서 하지 않음. 수료용 내보내기 폴더는 `E:\hesed-package`(포장 묶음이 아님)
- 소스와 패키지가 같은 커밋에서 나왔는지: 미확인 (내보내기는 커밋 전 작업 사본에서 만듦 → push 뒤 같은 내용인지 다시 확인)
- 다시 실행한 명령: [클라우드 확인] 새 폴더에 앱 폴더만 복사 후 `node src/server.mjs`, 수료용 도구 적용 후 `node src/standalone-server.mjs`
- 다시 실행한 시각(한국 시간): [클라우드 확인] 2026-11-01 13:55 / [내 PC 확인] 미확인
- 다시 실행한 결과: [클라우드 확인] 화면 200, 학생 대시보드 불러옴, PC 조회 응답 정상 / [내 PC 확인] 미확인
담당자 권한이나 제공 실행 환경 준비 때문에 멈췄다면 메시지 코드와 도움을 요청한 날짜를 적고 원인을 구분합니다. 키와 설정을 임의로 바꾸지 말고 가능한 기능·디자인 작업을 계속합니다.
- 기록: 0.2.21 공식 업데이트 도구가 `UPDATE_FILE_MODIFIED`(제공 파일 2개가 공식 0.2.11 값과 다름)로 멈출 것을 미리 확인 → 두 파일이 0.2.12 이전 공식 문구임을 대조한 뒤 도구 목록의 제공 파일 45개만 공식 해시로 대조해 교체(2026-11-01). 담당자 문의는 하지 않음
